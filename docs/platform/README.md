# 私人量化平台第一版

## 暂停与保留外部仓位切换环境

环境切换展示数据库准备、账户只读核查、后台重载、确认或恢复阶段及等待时间。已经完成迁移的 SQLite 数据库跳过迁移进程；准备期间持续更新启动器心跳。网页状态查询采用 3 秒超时，并按本次切换编号核对，忽略旧任务状态。目标账户预检查每个请求最多 5 秒；暂时网络、限频或时间校验异常只读重试一次，密钥和权限错误不重试。账户准备上限 45 秒、服务确认上限 30 秒，失败恢复原环境。实际耗时取决于网络与服务启动速度。

环境设置中的“最近切换结果与失败原因”显示最近五次结果。后台保留最多二十次切换记录，成功不会覆盖上一轮失败原因；记录仅含环境、阶段、分类原因和时间，不含密钥、签名或原始交易所异常。记录目录为 `storage/run/environment-switch-history`，不用于自动启动交易。

“暂停新开仓”只将本系统自动交易关闭，即使执行未就绪或环境待重启也可暂停；认证与请求环境核对仍保留。暂停不处理外部仓位／订单，不代表当前账户空仓，也不会清除风险或同步错误。

助手已暂停、没有系统持仓／未确认订单／平仓请求，且没有其他运行中的模拟或研究任务时，外部手工持仓与订单可留在原环境，允许切换。来源未知或系统与手工混合而无法确认的记录仍阻止切换；原环境持仓需由用户继续自行管理。切换不调用交易所平仓或撤单接口。

主网启动仍检查同步、逐仓、止损风险、可用余额和组合预算；支持外部仓位展示与环境切换不等于取消这些条件。本轮未改变实际环境或账户模式，也未提交交易指令。

## 手工订单与量化共存

交易助手根据交易所订单编号、本地记录和关联订单编号标记订单来源：本系统、外部／手工、未知。外部订单只展示，不发送撤单请求或接管其持仓。外部订单／持仓涉及的币种跳过新开仓；本系统持仓同币种出现外部订单时，也暂停自动退出，已有交易所保护订单继续由交易所执行。

其他币种可以使用扣除挂单、持仓保证金后的交易所可用余额。余额不再必须覆盖整份共享预算，实际数量仍受可用余额、费用、共享预算、组合风险与最小订单约束。外部开仓挂单的剩余名义金额计入总敞口，并预留币种持仓名额；相关性检查也包含外部开仓挂单币种。外部订单保证金已经包含在交易所可用余额扣减中，不重复扣除。名义金额与保证金金额不同。

来源或金额无法核实的挂单、对冲模式、已有无止损持仓仍阻止新开仓。手工订单成交后会重新核查实际持仓、止损与风险。手工仓位盈亏仍影响账户级风控；手工订单未来成交的风险不能由当前可用余额保证。所有本轮验证采用模拟账户，没有实际交易操作。

## 交易助手的主网／测试网执行

交易助手按实际生效的 Bybit 环境选择 REST、私有 WebSocket 与密钥；主网使用真实资金，测试网使用测试币。连接端点依据[Bybit 官方连接文档](https://bybit-exchange.github.io/docs/v5/ws/connect)。新版统一启动器自动重新加载后台服务，完成账户只读核查后刷新页面；切换期间交易操作不可用。两个环境继续使用独立数据库，研究／验证任务标记环境，异环境结果禁止应用。

主网需要 `.env` 中的主网密钥及 `LIVE_TRADING_CONFIRM=I_UNDERSTAND_LIVE_TRADING`、交易所行情、平台执行开关开启，并满足账户同步、逐仓单向、预算、待确认订单与风控检查。切换和保存参数不会发送启动请求。旧版页面不提供环境与配置指纹的启动请求会被主网拒绝。

本次验证只使用本地临时数据库、模拟账户和替代 SDK；未启动用户的交易进程或调用真实账户的下单、撤单、平仓、杠杆与保证金修改接口。主网实际连接和成交未验证。内部 `testnet` 模块、表名、工作进程标识与配置键暂保留兼容，名称不再决定执行环境。

## 交易助手的简化操作入口

交易助手顶部独立“共享预算”卡片显示已保存预算和可用余额，提供明显的“修改预算”按钮；点击后定位并聚焦预算输入框。新账户共享预算默认200 USDT，可在10～100000 USDT范围内修改，保存后生效，不自动启动交易。预算按环境分别保存；实际下单数量还受剩余可用余额、费用、名义金额与风险约束。修改时要求暂停、账户空仓、无本系统待处理订单或平仓请求，外部挂单可保留。右上角显示当前主网／测试网；主网支持真实资金执行，账户查询页面仅负责显示余额，不代表整个主网只能查询。

“账户全部持仓”默认展开，放在启动操作前，同时在交易记录入口显示。表格包含来源、方向、数量、入场价、标记价、浮盈亏、止损和系统处理方式。能确认本系统归属的标记“本系统”；手工或其他程序的标记“外部／手工”；存在系统开仓记录但实际持仓无法匹配的标记“归属未确认／混合”，不自动接管。旧后端只提供系统持仓时明确提示重启，不将其误称为已获取全部账户持仓。

若仍收到旧版“检测到非本系统持仓或挂单”的执行错误，界面提示重启平台加载按币种隔离规则，并保留禁止启动状态，避免界面与旧进程实际行为不一致；新执行进程完成同步后更新状态。

交易助手默认打开“运行面板”，显示当前已保存参数、执行确认、启动／暂停／平仓、信号扫描和持仓。“策略设置”用于修改并保存参数，成交量、波动和趋势过滤条件默认折叠；“研究验证”集中周期回测、独立验证、参数预览与组合研究；“交易记录”集中订单、成交、净盈亏和资金流水。账户详情、首次账户初始化与操作帮助按需展开。

首次使用先在策略设置中保存配置，再到研究验证完成回测与验证，预览差异后应用。保存或应用后返回运行面板，但不会自动启动交易。日常操作在运行面板查看执行确认，扫描已保存币种，再手动启动当前环境交易。页面切换保留未保存的表单；表单与已保存配置不一致时禁止启动，可保存或加载已保存配置。

## 数据一致性、稳健性诊断与测试网验收

新增回测会记录行情连续性检查、零成交量计数及规范化数据指纹；负成交量、负成交额或非有限数值不会通过校验。组合详情的“数据一致性报告”逐币种显示成交价与标记价偏离、资金费最大记录间隔及档位采集时间。结算周期可能历史变更，因此空档提示不等于断言遗漏；仍不补造资金费。接口兼容最低档空扣减值和最高100%维持保证金率，非最低档缺失扣减值仍拒绝采纳。依据公开接口的最低档标记将空扣减值按零处理；高保证金率研究模型避免除零并检查保证金不足。

新研究任务与样本保存实际交易环境；研究进程环境与任务环境不匹配时，在获取行情前失败。优化恢复还核对已保存样本的环境；旧交易所样本没有环境记录时要求新建任务，不将旧数据重新标记成当前环境。旧完成结果保持原记录。普通新回测在首次采集时补充实际环境标记，源数据不含密钥。风险档位字段参考[Bybit官方风险限额接口](https://bybit-exchange.github.io/docs/v5/market/risk-limit)，空扣减值只在接口明确标记为最低档时按零处理。

新自动优化任务完成原搜索后，对候选增加三类诊断：研究区间主要周期参数上下约10%的邻域检查、独立验证区间1/2/3倍手续费和滑点压力、最多3个滚动样本外窗口。每次滚动只使用此前已收盘数据，在固定邻域中按研究约束与目标评分选择，再测试下一段。原搜索不使用这些验证结果重新排序；诊断不改变原应用资格。展开候选行或查看其验证回测即可阅读报告。诊断会增加研究时间，仍可取消；旧结果不补造报告。窗口独立初始化资金、不延续跨窗口持仓；邻域不覆盖完整参数空间，单币诊断仍沿用单币回测的成本范围。

测试网验收入口：`python scripts/testnet_smoke.py --check`只读核对就绪条件；`--execute`在明确授权且助手暂停、账户空仓、无未确认订单、逐仓、至少200测试USDT时才提交上限12USDT的小额测试。测试数据库与原平台分离，旧版平台状态读取不要求迁移。新增流程包含实际挂单及撤单、市价提交后模拟丢弃响应、按同一订单编号恢复成交、重新建立数据库连接与客户端后证明仓位归属，再退出并核对账本。仅清理本次已识别订单与持仓。

验收报告保存到`artifacts/testnet/smoke-*/report.json`，“运行状态与备份”显示最新基础检查与未测试项目。止损存在不等于已观察到止损触发；真实部分成交、止损实际触发、长时间断网及资金费结算事件仍单独列为未测试。提交成功后丢弃响应只是可控故障模拟，客户端重建不代替操作系统进程崩溃演练。交易助手已接入主网执行路径，主网真实下单验收尚未进行。本轮额外公开历史接口检查保存在`artifacts/research-quality/latest.json`，该文件仅记录本次检查，不自动代表所有币种和日期区间都合格。

## 组合研究、运行恢复与交易回放（0008）

重启统一启动器后，在“交易助手”先保存至少两个币种及预算、周期、策略模板，再使用“多币种共享预算回测”。任务进入独立研究队列；完成后查看详情，再用研究结束后的区间创建验证任务。验证沿用研究的币种、配置、成交假设和合约档位快照。验证完成后会出现在原“应用研究参数”列表，需要先预览差异；应用仍保持暂停，不会自动启动交易。预算和账户风险设置保留当前助手值，差异表显示研究值供核对。

组合回测共用现金、名义金额与计划风险额度，持仓和待成交挂单共同占用额度。信号来自上一根已收盘K线；成交模型支持市价IOC剩余撤销、PostOnly开盘价代理、限价触及与过期、成交量参与率和部分成交。限价模型仅用于研究，当前助手实际开仓仍使用市价单。结束结算假设可完全成交。

历史成交K线、标记价格K线和资金费均来自公共接口。标记价格必须逐根对齐；启用资金费且完全没有记录时任务失败，不自动填零。结果显示每币种记录覆盖、成本与模型限制。资金费接口返回的记录不能证明整个区间无缺失；K线内部结算价采用标记开盘价近似。合约过滤与维持保证金档位是采集时快照，不是历史档位。逐仓强平包含平仓费近似与剩余保证金损失上限，不复现真实订单簿、保险、ADL或交易所完整风险计算；不能把回测当成实盘成交保证。

统一启动器只监督自己创建的服务，异常退出按退避重启，默认10分钟内最多5次；达到上限会暂停本地助手并停止自身服务。执行进程重启或核查失败后，需连续两次成功核对且无账本异常，才允许新开仓，已有仓位保护和订单查询仍运行。提醒在页面“运行状态与备份”显示，包括进程离线、未确认订单、未保护持仓、账户核查异常及备份异常；不发送外部通知。

SQLite默认启动时备份，此后每24小时备份，保留最近7份同一数据库的备份。使用SQLite在线一致性快照，并复制数据库引用的行情Parquet与归档JSON文件；不复制环境密钥。数据库完整性、外键和文件SHA256均校验；文件缺失会标记备份不完整。备份位于`storage/backups/scheduled`；页面“校验最近备份”再次验证，不覆盖运行数据库。本轮测试在独立临时目录完成了恢复演练；PostgreSQL仍需部署方备份服务。间隔、保留数量与重启次数在`.env.platform.example`列出，已有本地配置不会被覆盖。

`0008_order_context`为新提交订单保存不可随配置编辑改变的决策快照。交易周期“查看回放”按开仓编号读取当时规则、预算、方向、计划风险与逐笔实际成交；旧订单没有快照时明确提示未记录。统一启动器升级前会备份既有SQLite数据库。页面、图表按需加载，界面组件按需导入；开发预加载配置避免首次打开页面时因依赖优化自动刷新。

Vue 3 / TypeScript / Element Plus / ECharts 前端，FastAPI 接口，SQLAlchemy 数据层，Alembic 迁移，独立 Python 模拟交易引擎与独立回测进程。Docker 部署使用 PostgreSQL；Windows 本地启动默认使用 SQLite，方便先联调。

## Windows 本地启动

当前工作区已安装依赖并生成本地平台配置，可直接在项目根目录运行：

```powershell
.\.venv\Scripts\python.exe -m quantpilot.platform.launch
```

打开 http://127.0.0.1:5173 即可直接进入工作台，默认个人模式无需访问凭证。一个终端会同时管理 API、模拟交易引擎、独立测试网执行、回测进程和前端；Ctrl+C 停止全部子进程，日志保存到 `storage/logs/`。关闭启动终端会终止本地服务；长期运行请使用下方 Docker 方式。

在新机器首次安装，或希望分别启动服务时，使用以下步骤。

在项目根目录安装后端并生成独立平台配置（不会修改交易所 `.env`）：

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[platform,dev]"
.\.venv\Scripts\python.exe -m quantpilot.platform.bootstrap
.\.venv\Scripts\python.exe -m alembic upgrade head
```

打开五个 PowerShell 终端。前四个保持项目根目录，分别启动：

```powershell
# 终端 1：API
.\.venv\Scripts\python.exe -m uvicorn quantpilot.platform.api:create_app --factory --host 127.0.0.1 --port 8000

# 终端 2：独立模拟交易引擎
.\.venv\Scripts\python.exe -m quantpilot.platform.engine

# 终端 3：独立回测进程
.\.venv\Scripts\python.exe -m quantpilot.platform.research_worker

# 终端 4：独立测试网执行与风控
.\.venv\Scripts\python.exe -m quantpilot.platform.testnet_worker
```

第五个终端启动前端：

```powershell
Set-Location frontend
npm.cmd ci
npm.cmd run dev
```

打开 http://127.0.0.1:5173 即可直接进入。`.env.platform` 默认 `PLATFORM_AUTH_ENABLED=false`，页面和 API 都不要求平台凭证；本地启动仍只绑定 `127.0.0.1`。

若以后需要访问验证，可将 `PLATFORM_AUTH_ENABLED=true`，填写至少 32 字符的 `PLATFORM_ACCESS_TOKEN` 并重启。开启后页面才显示凭证输入与锁定按钮，API 强制校验凭证。平台凭证与交易所 API Key 不同。

## 行情与账户环境

行情中心新增多币种列表、搜索、排序和数据库自选。真实行情模式动态读取交易所当前可用的 USDT 永续合约，演示模式提供 16 个模拟交易对。点击行内交易对或“查看”进入单币 K 线，策略与回测的交易对选择同样来自动态目录。

星标自选按 Bybit / Binance 分别保存，刷新页面和重启服务后保留。行情快照每 15 秒更新，服务端快照缓存 10 秒，交易对目录缓存 5 分钟；已下架或缺少行情的自选会提示并允许移除。升级旧工作区时运行 `python -m alembic upgrade head`，统一启动器会自动执行迁移。

默认 `PLATFORM_MARKET_SOURCE=demo`，使用合成价格，不访问交易所账户。界面明确显示演示标记，没有默认策略或虚构成交。

Bybit 测试网使用 `.env` 的 `BYBIT_TESTNET=true`。需要保留主网密钥时，可另外填写 `BYBIT_TESTNET_API_KEY` 与 `BYBIT_TESTNET_API_SECRET`：测试网模式下，只要存在任一测试网专用字段，就只读取这两个字段，即使为空也不会回退到主网密钥；主网模式仍读取 `BYBIT_API_KEY` 与 `BYBIT_API_SECRET`。专用字段都不存在时兼容原有配置。平台查询测试网行情和余额需设置 `PLATFORM_MARKET_SOURCE=exchange`；策略仍为本地模拟，填写测试网密钥不会自动启用交易所下单。修改后重启平台。

网页右上角滑动开关和“交易所账户”顶部都可以切换 Bybit 主网／测试网，默认测试网。首次升级需重新运行 `python -m quantpilot.platform.launch` 加载新版统一启动器，此后切换无需手动重启。切换期间显示“切换中”，“当前”在后台核查成功后更新；页面自动刷新并保留所在页面，余额与预算从新环境加载。失败恢复原环境；两个环境的自动交易均保持暂停，需自行启动。旧启动器和独立启动 API 不提供自动切换，页面提示更新启动器；PostgreSQL 使用独立部署。

主网需要主网密钥及 `LIVE_TRADING_CONFIRM=I_UNDERSTAND_LIVE_TRADING`。保存环境时仍固定 `DRY_RUN=true`、`TRADING_ENABLED=false`，避免启动旧的独立交易入口；平台交易助手由 `PLATFORM_TESTNET_EXECUTION_ENABLED` 控制（沿用旧变量名，现支持两个环境）。目标环境有系统持仓、待确认系统订单或平仓请求时拒绝切换；外部订单与持仓只查询展示，不操作。

本地 SQLite 会为两个环境分别保存数据库路径：首次切换保留原环境现有数据库，另一环境新建数据库；切回时恢复原路径，启动器自动执行迁移。原策略、自选和研究历史仍在原环境保留，不会复制到新环境。`.env.platform` 中的 `PLATFORM_BYBIT_TESTNET_DATABASE_URL` / `PLATFORM_BYBIT_MAINNET_DATABASE_URL` 保存两个路径，备份时需要保存两个数据库。任何运行中策略、模拟持仓或未完成回测／优化会阻止切换。PostgreSQL 部署暂不支持网页切换，请使用独立部署配置与数据库。

要读取交易所真实行情，将 `.env.platform` 改为：

```env
PLATFORM_MARKET_SOURCE=exchange
```

然后重启 API、引擎与回测进程。`.env` 决定交易所环境与凭据。如果使用 Bybit 主网密钥：

```env
EXCHANGE=bybit
BYBIT_TESTNET=false
LIVE_TRADING_CONFIRM=I_UNDERSTAND_LIVE_TRADING
DRY_RUN=true
TRADING_ENABLED=false
```

账户查询只在页面点击“查询余额”时请求私有只读接口。平台不返回 API Key 或 Secret。

策略和回测任务绑定创建时的行情来源。切换来源后，旧来源策略不会混用价格；请在新来源下创建策略与回测。“策略管理”执行本地模拟订单，“交易助手”独立执行 Bybit 测试网订单。

## 测试网交易助手

统一启动器自动迁移至 `0005_testnet_trading`，增加共享账户、持久化订单意图与已对账持仓表。`.env.platform` 设置 `PLATFORM_TESTNET_EXECUTION_ENABLED=true`、`PLATFORM_MARKET_SOURCE=exchange`，`.env` 使用 Bybit 测试网的 USDT 永续合约配置及专用测试网密钥。引擎同步测试账户；助手默认暂停，必须在网页明确点击启动才开仓。普通模拟策略不会变成交易所订单。

先在 Bybit 测试网领取足够 USDT，等待余额同步，然后在空仓、无挂单时点击“设置空仓测试账户为逐仓／单向”。共享预算默认 200 USDT，默认每笔计划风险 0.5%、组合风险 1%、日亏损暂停 2%、高点回撤暂停 5%，最多 2 个持仓、2 倍杠杆，总名义金额不超过预算。费用与滑点余量计入风险仓位，数量向下取整，不能满足最小订单则跳过。默认扫描 BTC、ETH、SOL 的 1 小时 EMA 双均线信号；只在已收盘信号出现时交易，不保证启动后立即开仓。

开仓附带标记价格触发的交易所止损，可选止盈；止损未生效时请求只减仓退出。订单编号和意图先提交数据库，再请求交易所。HTTP 接受不代表成交，后续通过订单状态和实际持仓确认；未知状态会阻止新开仓并查询原编号，不盲目重发。只管理匹配本系统成交记录的单向持仓，外部持仓／未知挂单会阻止开仓。暂停后继续对账与持仓保护，已在提交中的订单仍可能成交；平仓并暂停只退出已确认的本系统仓位。风控触发后暂停并退出持仓，空仓且所有订单确认后方可重置基线。

预算权益等于预算加 USDT 钱包权益变化，钱包含浮盈亏与费用；日亏损按上海自然日开始权益，高点回撤按初始预算金额阈值判断。首次零余额不建立资金基线；之后充值或手工交易仍可能影响统计，使用专门测试账户，必要时空仓暂停后重置基线。账户保护按轮询触发，交易所止损独立于进程；计划风险不是损失保证。主网执行沿用相同风控，启动时必须提交当前环境及已保存参数指纹；主网实际成交尚未验收。

相关接口：`GET /api/trading/status`；`POST /api/trading/configuration`、`/api/trading/scan`、`/api/trading/prepare-isolated`、`/api/trading/command`。命令为 start、pause、flatten、reset。私有请求签名先同步交易所时间，再使用单调时钟推进，避免本机时间漂移；同步异常阻止请求。执行开关关闭会停止测试网同步与执行，因此已有持仓时优先用网页暂停或平仓。切换环境也要求助手停止、空仓且没有未确认订单。

## 操作语义与恢复

- 创建策略：独立模拟资金账户，默认暂停；可选择 EMA / RSI、EMA 双均线、RSI 均值回归、区间突破、布林带回归，保存配置 v1 参数快照，支持成交量、ATR、ADX 过滤。
- 启动：引擎轮询行情，仅对最新已收盘 K 线计算一次信号。成交价采用本次轮询观察到的最新行情价格并施加滑点；不假设过去开盘价仍可成交。
- 暂停：停止新开仓及信号反手，保留持仓；已有持仓继续更新估值并执行止损、止盈及最大回撤保护。止损／止盈平仓后仍为暂停，不重新开仓；最大回撤触发后禁止重新启动原实例。
- 平仓并暂停：保存平仓意图，引擎取得行情后完成模拟平仓。行情不可用时保留意图并重试，不伪造平仓成功。
- 费用：开仓费即时扣除；平仓现金变化为毛盈亏减平仓费。两笔现金变化合计为完整交易净盈亏。
- 风控：不允许超过实例最大名义金额与模拟可用资金的开仓；支持本地模拟止损止盈及最大回撤平仓暂停，未模拟杠杆保证金、资金费率、强平及交易所止损。
- 恢复：数据库保存状态、持仓、最后处理的信号 K 线；重启不补做错过的历史信号，不重复已提交的模拟成交。
- 单实例：引擎与回测进程分别使用数据库租约，租约有效期 120 秒。强制终止后，替代进程最多等待 120 秒接管；所有成交与游标在同一事务中落库。
- 回测：API 仅排队，独立回测进程计算；价格样本保存到 `storage/market/*.parquet`。进程中断后可重算未完成任务。
- 心跳：页面显示数据库租约状态，不表示已验证交易所连通性。市场处理异常会显示在策略与事件记录中。

新回测使用每根收盘的盯市权益，包含持仓浮动盈亏、手续费与滑点，下一根开盘成交、样本末尾平仓。旧回测记录仍按原有口径显示。历史日期区间支持分页拉取、预热与严格完整性检查；参数批次固定相同数据区间，最多 9 组。每个结果记录配置、样本指纹和风控拒绝次数，可以沿用配置创建暂停的模拟策略。验证标签仅记录用途，未自动执行样本外拆分。

自动优化独立于上述手动标签：`POST /api/optimizations` 自动按切分日期分开研究与验证，只把研究评分传给 Optuna TPE。最多 200 次试验，保留 5 个不同候选；验证支持 1–3 个固定参数、独立资金的连续窗口。结果、进度、试验检查点落库，研究进程共享租约串行处理普通回测与优化任务。取消、恢复和行情指纹校验均由服务端执行。`GET /api/optimization-space` 返回当前模板允许的搜索范围。升级至 `0004_optimization` 并更新 platform 依赖后使用。

## 曲线加载与手动归档

`GET /api/strategies` 只返回策略摘要，不包含曲线。打开详情后调用 `GET /api/strategies/{id}/curve`，首次取最近 1000 点，后续使用 `since_id` 增量读取（包含游标对应的点，以更新同一根 K 线的权益）。关闭详情或切换页面后停止轮询。权益曲线按 K 线周期保存最后一次估值，最大回撤按引擎每次轮询计算并保留全程统计。

演示近期与历史行情共用生成函数；相同币种、周期、时间戳的已收盘 OHLC、成交量、成交额完全一致。未收盘演示 K 线按周期进度插值，并累计成交量，不用于已收盘信号。演示数据是合成数据。

归档入口在“总览”底部，默认保留最近 90 天，允许 30–3650 天。先预览各类数量，再确认归档；预览一小时有效。API 为 `POST /api/maintenance/archive/preview`（`retention_days`）和 `POST /api/maintenance/archive/execute`（预览 `id`），沿用平台鉴权。

- 每批最多 10000 条权益记录、10000 条事件、10 个回测明细及 10 个优化明细。大批量可分次预览执行。
- 按记录创建时间或任务结束时间筛选，保留每个策略最新权益点；排队中、运行中、取消中的任务不归档。
- 权益与事件写入 Parquet；任务明细写入 JSON，保留原任务配置与结果。每批都有 `storage/archive/<编号>/manifest.json`，记录数量、路径、原始记录指纹和文件 SHA-256。
- 在数据库事务中复核预览指纹，回读导出数据并验证数量、内容与文件指纹，之后才删除旧权益／事件，或把任务的大结果替换为汇总和归档引用。写入或校验失败时事务回滚，原数据保留；失败产生的文件保留用于排查，重新预览可重试。
- 回测与优化详情打开时验证归档指纹并读取完整结果。文件缺失或损坏时明确报错；配置、来源编号与推广约束仍保存在数据库中。
- 保留策略累计权益、峰值、全程最大回撤、持仓、订单和任务编号。不删除或移动 `storage/market` 中的共享行情样本，因此未完成优化的检查点和历史回测引用不受影响。
- 归档减少数据库热数据，释放的数据库页可复用，不保证 SQLite 文件立即缩小。归档文件仍占磁盘；当前不自动清理行情文件或迁出归档。

备份应整体保存数据库、`storage/archive` 和 `storage/market`；Docker 对应 PostgreSQL 卷和研究数据卷。旧权益／事件可通过 manifest 定位并读取 Parquet；历史任务继续从原详情页面打开。本次没有自动归档现有个人数据，无需新增数据库迁移。

## PostgreSQL / Docker 部署

安装 Docker 后，在根目录执行：

```powershell
docker compose --env-file .env.platform up --build -d
```

打开 http://127.0.0.1:8080 。Compose 包含 PostgreSQL、迁移、API、引擎、回测进程与 Nginx 前端，数据库与行情使用持久化卷。`POSTGRES_PASSWORD` 由 bootstrap 生成；没有默认数据库密码。

前端端口仅绑定本机。远程私人访问可使用 SSH 隧道转发本机端口；如公开到网络，需单独配置 HTTPS 和访问控制。本次没有部署到公网。

若已有 `.env.platform` 而缺少 `POSTGRES_PASSWORD`，请填写随机长密码。密码用于 Compose URL，建议使用字母数字或十六进制，避免未编码特殊字符。

## 验证

交易助手新增“当前执行参数与确认”：显示已保存的模板、币种、周期、预算、过滤条件及验证来源。表单修改未保存时禁止启动，可以保存或点击“加载已保存配置”；后台刷新不覆盖正在编辑的草稿。启动请求携带当前已保存配置指纹，其他页面已改配置时拒绝旧版本启动。启动成功仅代表指令已提交，须等待执行进程完成一轮检查后确认。确认要求参数指纹一致、进程租约在线、检查不超过60秒且晚于最近启动／暂停指令；重新启动不能复用旧运行的确认。

执行进程保存本轮使用的参数及最后实际信号扫描摘要，页面明确区分它与手动扫描。参数确认不代表已经成交；恢复核对、待确认订单、持仓管理、开仓检查拒绝和等待信号分别显示。研究指引不自动标记为已完成，研究和因子报告不自动进入执行参数；需要保存或应用验证结果。默认／手动配置显示未关联验证回测，应用后修改的配置明确标注来源已修改。

新增“因子诊断”：交易助手的策略参数下方解释因子与过滤的区别，扫描结果展开“查看已收盘因子”显示EMA趋势差、20根动量、RSI、成交量倍数、ATR波动和ADX强度。数值仅使用已经收盘的行情；成交量均值不包含当前K线。模板决定入场事件和多空，成交量／ATR／ADX决定是否过滤，不会根据强度值直接改成做多。

新创建的单币回测、周期对比、优化候选及组合回测保存因子研究报告。周期对比行点击“查看因子诊断”；普通回测结果和优化候选展开同名报告；组合报告分币种显示。历史结果不改写，没有报告时提示重新回测。单币和组合诊断默认在有效样本内按70%／30%切分，优化候选使用任务指定的研究／验证切分。内部切分不等于独立后续验证。

因子报告检查持有1、4、12根K线的单币时间序列Spearman秩相关，用信号后下一根开盘至持有期限后的开盘计算收益。每个期限隔相应根数取样，研究段剔除退出时间跨越切分的标签；方向及20%／80%分组阈值仅由研究段确定，留出段不参与因子排序或交易参数应用。至少30对非恒定样本才报告相关，尾部每组至少5次才报告方向均值。尾部收益只是每次算术均值，扣双向固定手续费及滑点，不是完整策略收益，未计资金费、持仓限制或强平。

单币回测／优化候选若启用成交量、ATR或ADX过滤，报告额外在同一留出段逐项关闭一个条件，保持其他规则、手续费、滑点和资金设置，比较收益、回撤和交易数。诊断不会更新原候选评分、应用资格或正在运行的参数。组合报告当前不做过滤关闭对照，组合限制和真实合约成本仍由原组合回测评估。

因子间训练段秩相关绝对值达到0.8时提示可能重复，不能把多个相似指标视为多份独立证据。多次看留出结果后调参会消耗独立性，应保留另一个后续区间；诊断不提供显著性结论、自动权重、盈利保证或AI自动下单。秩相关和分组研究思路可参考 [Alphalens 官方实现](https://github.com/quantopian/alphalens/blob/master/alphalens/performance.py)，本项目采用单币时间序列口径，与该工具常用的多资产横截面IC不同。

交易助手默认启用 Bybit 测试网私有订单、成交、持仓及钱包推送。推送只唤醒 REST 对账，不直接写入成交或资金；断线、鉴权失败或对账期间出现新事件时暂停新开仓，连续两次完整核对成功后恢复开仓资格。已有仓位的交易所止损及保护性平仓不依赖推送连接。页面展示连接状态和最近开仓检查原因。推送使用与 REST 相同的 Windows 系统代理，重连采用最长30秒的退避；每轮处理至少间隔2秒，并保留定时查询兜底。

新开仓先更新账户、已收盘信号和合约限制，设置杠杆后、提交订单前再核对一次。默认拒绝超过5秒的报价、超过20基点的买卖价差、相对信号价格超过0.5%的偏离、最优报价深度不足、标记价格已越过保护价，以及风险预算或可用保证金不足。检查失败不会自动重发订单；已经登记的意图仍保留用于排查。行情、账户和最终检查不是交易所原子操作，快速跳价仍可能使实际成交偏离检查报价。

可运行只读连接验收：`.\.venv\Scripts\python.exe -m scripts.testnet_stream_check --seconds 30`。报告保存于 `artifacts/testnet/stream-check.json`，只包含连接状态和计数，不保存密钥、签名或推送原文。`reconciled=false` 在此只读脚本中正常，因为脚本不运行账户对账。如需明确使用定时查询模式，在 `.env.platform` 设置 `PLATFORM_TESTNET_STREAM_ENABLED=false` 并重启；默认值为true。私有连接协议依据 [Bybit 官方连接说明](https://bybit-exchange.github.io/docs/v5/ws/connect)。

## 后续实盘阶段

### 风险仓位与周期对比

界面更新后必须停止旧启动终端并重新运行统一启动器；仅刷新网页不会重载后端。新接口返回404时，周期对比和验证列表会明确提示重启。默认研究区间预留最近30天用于后续验证：三个周期研究完成后，选择一个结果点击“创建后续验证”，保留研究配置，在不重叠的后续区间验证。验证任务完成后，下方参数列表自动刷新。标签为“研究”的任务不会出现在验证参数列表中。

提交回测后显示成功提示及任务状态，研究服务离线时提示任务正在等待服务恢复；可以切换历史结果组。测试网交易助手默认自动选择多空：EMA向上交叉做多，向下交叉做空，没有新交叉等待，而非均线一直向上就持续开多。其他模板使用各自的信号规则。扫描表区分均线位置、入场信号依据及风险拒绝原因；反向信号先处理原仓位退出，新开仓仍通过风险与订单确认检查。

交易助手新增“15分钟 / 1小时 / 4小时对比”。先保存币种、规则、预算及风险设置，再选择同一起止时间创建三项研究任务。时间需对齐 UTC 每四小时边界，三个周期各至少100根交易区间K线。默认最近90天，研究和独立验证区间应自行分开，验证标签本身不证明独立性或盈利。

这些回测与测试网执行共用 `quantpilot.sizing.allocation`：按单笔和组合止损风险、成本、预算及可用资金计算数量，向下按步长取整，无法满足最小数量／金额时跳过。保存当前合约限制及采集时间用于复核，不能视为历史合约限制。原固定数量回测保持兼容；风险数量回测不可直接转换为固定数量模拟策略。

风险数量回测使用 OHLC 检查盘中保护价；跳空止损按开盘价处理，同时触及止盈止损按止损优先，并计入双向手续费及滑点。账户保护共用 `quantpilot.account_risk.evaluate_account_risk`，日亏损与高点回撤金额均除以固定共享预算，日基准按上海日期重置。例如预算200、权益高点250、当前239，对应风控回撤5.5%；配置5%时会暂停。绩效报告的标准最大回撤仍为4.4%，两种口径在页面分开展示。风险回测只使用共享账户风险限制，不再额外触发模板中的模拟回撤设置。

新风险回测结果保存 `fixed_budget_v1` 风控摘要与最大预算回撤／日亏损百分比；历史结果不自动改写，未记录版本时提醒重新回测。它仍不模拟历史资金费、保证金强平、标记价格路径或订单簿成交；单币对比不代表多币组合收益。资金管理算法一致不代表实际成交与回测完全一致。

对比表显示收益、回撤、交易次数、平均每笔净收益和跳过开仓次数，失败任务显示原因。应用验证回测仍保留交易助手当前风险设置，并要求预览确认；不会自动启动交易。账户保护区增加执行服务在线状态、账户快照有效性及无止损仓位提示，快照有效性使用实际采集时间，不使用最近错误更新时间。

参数应用预览增加应用前、应用后及回测来源参数对比。页面默认保留当前扫描币种，也可选择仅使用回测币种；切换选择会清除预览与确认。保留的其他币种未被这项单币回测验证时，须单独确认。预算、杠杆与账户风险参数保持当前设置；币种、规则、周期与成本按预览应用。指纹同时绑定当前配置、研究结果风控摘要和币种选择，配置变化必须重新预览，应用后保持暂停。来源记录保存应用前后配置、币种处理方式及未验证币种列表。

`0007_testnet_recovery` 增加成交序列、交易流水关联、开仓结束时间和研究参数来源。统一启动器运行五个服务，测试网执行由 `testnet_worker` 独立处理，原 `engine` 只处理本地模拟。Docker Compose 同步增加 testnet 服务。已有 SQLite 升级前自动创建一致性备份；PostgreSQL 备份仍需由部署方执行。

助手允许预览并应用验证标签的 Bybit 交易所行情回测：接口为 `GET /api/trading/research`、`GET /api/trading/research/{id}/preview`、`POST /api/trading/research/{id}/apply`。应用要求暂停、空仓且没有未确认订单，并核对预览指纹和仓位模型差异；只复制规则、币种、周期与成本，不复制固定数量、不启用交易。来源、参数、指标、数据指纹和应用时间持久化；编辑配置后标记来源已修改。旧结果没有环境信息时明确显示未记录，不推测来源。

资金流水异常时保留已核实账面权益，额外用可信浮盈亏变化计算保护参考权益，未知现金变化不直接当收益或亏损。每日亏损／回撤保护继续检查已确认的价格损失；新开仓仍被阻止。成交盈亏按时间／序列更新剩余成本，在逐笔盈亏流水齐全时采用交易所现金流核对；无法确认顺序或结束归属的交易标记待核查。已确认不存在的旧开仓退出认领范围，不仅凭同价同量认领后来的仓位。

平台已支持 Bybit 测试网的订单意图、逐笔成交与仓位对账、合约过滤、原生止损及共享预算。尚未完成主网执行验收；WebSocket 事件流、限频与长期断线演练、完整保证金／强平回测仍需后续完善。主网执行路径已通过隔离模拟接口检查；本次未向主网提交、撤销或平仓任何订单。

## 测试网成交账本与恢复（0006）

`0006_testnet_journal` 增加独立的逐笔成交和 USDT 资金流水表，以及订单撤单请求、开仓关联与资金基线字段。升级前应备份 SQLite；统一启动器仍自动迁移到最新版本。旧历史不会用推测价格补造成交。

交易助手显示资金账户与统一交易账户余额、基线后的净划转、交易周期净盈亏、逐笔成交和资金流水。净划转通过 TRANSFER_IN／TRANSFER_OUT 等资金事件核算，从钱包权益变化中扣除；手工交易仍属于账户收益变化，建议专用账户。账户初始化记录资金基线，重置基线要求暂停、空仓且所有订单已确认。交易周期通过本系统开仓编号关联退出成交，计算已实现价差、开平仓费用和资金费，不包含尚未平仓部分的浮盈亏。

执行进程按交易所时间窗口分页读取流水，重读最近 24 小时以补齐延迟记录，按唯一成交编号／资金记录去重。钱包现金变化与流水变化不一致时保留上次已核实权益，显示核查提示并阻止新开仓，仍处理已确认持仓的止损缺失和请求平仓。记录延迟超过重读窗口时需历史导入，不能直接清空错误。

未知订单会同时通过订单记录和逐笔成交恢复；足额成交可以确认 Filled。网页“请求撤单并暂停”保存请求，执行进程只有在查询到原订单仍挂单时才撤单，交易所确认终态后释放通道。不把查询不到视为从未提交，也不自动重发。部分成交的未确认开仓不会阻止对已确认持仓的保护性只减仓退出，同时请求取消剩余开仓。

多币种候选按最近 24 根已收盘 K 线的中位成交额排序；最多一个新开仓进入每轮执行。默认相关性上限 0.85，用最近 100 根已收盘收益率的绝对相关性限制增加持仓；不足 30 个共同样本或无法计算时不增加风险，设置 1 可以关闭此过滤。流动性排序不代表预测收益。

`scripts/testnet_smoke.py --execute` 是需要明确授权的小额测试脚本：只支持测试网，要求连续助手已暂停、没有持仓／挂单／未确认订单、逐仓且至少 200 测试 USDT。单次测试名义金额不超过 12 USDT，订单与报告存入 `artifacts/testnet/smoke-*` 独立数据库，结束后核查本次持仓和订单。它不会启用持续自动交易。未知结果保留恢复记录，严禁改成主网执行。
